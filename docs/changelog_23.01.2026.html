⚙️ Обновление конфигурации приложения

Изменения в core/config/settings.py: Добавлена логика автоматического определения окружения и выбора соответствующей базы данных.

Новый код определения окружения:

ОБНОВЛЕН core/config/settings.py
@dataclass class DatabaseConfig: """Конфигурация базы данных""" path: str = None # Будет определяться динамически def __post_init__(self): """Динамически определяем путь к БД в зависимости от окружения""" if self.path is None: # Определяем корневую директорию проекта root_dir = Path(__file__).parent.parent.parent # Проверяем наличие маркера production prod_marker = root_dir / "prod.marker" is_production = prod_marker.exists() if is_production: # Production окружение - используем отдельную базу self.path = "db/prod_salary.db" print(f"[CONFIG] Окружение: PRODUCTION") print(f"[CONFIG] Используется база данных: {self.path}") print(f"[CONFIG] ВНИМАНИЕ: Работа с реальными данными!") else: # Development/Current окружение - используем тестовую базу self.path = "db/salary.db" print(f"[CONFIG] Окружение: DEVELOPMENT/TESTING") print(f"[CONFIG] Используется база данных: {self.path}") # Создаем директорию для базы данных, если её нет db_path = Path(self.path) db_path.parent.mkdir(parents=True, exist_ok=True)
def get_environment_info() -> tuple[bool, str]: """ Определяет окружение и читает информацию из маркера. Returns: tuple[bool, str]: (is_production, marker_text) """ root_dir = Path(__file__).parent.parent.parent prod_marker = root_dir / "prod.marker" if prod_marker.exists(): try: # Читаем текст из маркера marker_text = prod_marker.read_text(encoding='utf-8').strip() if not marker_text: marker_text = "РЕАЛЬНАЯ БАЗА ДАННЫХ" return True, marker_text except Exception as e: print(f"[CONFIG] Ошибка чтения prod.marker: {e}") return True, "РЕАЛЬНАЯ БАЗА ДАННЫХ" return False, ""
@property def display_name_with_version(self) -> str: """Возвращает название приложения с версией и предупреждением для production""" base_name = f"{self.display_name} v.{self.version}" if self.is_production: if self.production_warning: return f"{base_name} - {self.production_warning}" else: return f"{base_name} [PRODUCTION]" else: return base_name
Результат: Приложение теперь автоматически определяет, в каком окружении оно запущено, и использует соответствующую базу данных. В production окружении в заголовке окна отображается предупреждающий текст из файла prod.marker.

💾 Система автоматического резервного копирования

Инновационная функция: Перед каждым обновлением скрипт автоматически создает резервную копию текущей версии с сохранением номера версии и даты.

Логика резервного копирования:

НОВАЯ ФУНКЦИЯ create_backup_before_update()

Функция в update_prod.py, которая:

  • Создает папку .backup если её нет
  • Читает версию из version.txt
  • Создает папку .backup/{версия}_{дата_время}/
  • Копирует все файлы из prod кроме .backup, db, prod.marker
  • Создает файл _backup_info.txt с информацией о резервной копии
prod/
├── .backup/
│ ├── 0.1.2_20250122_143045/
│ │ ├── _backup_info.txt
│ │ ├── desktop/
│ │ ├── core/
│ │ ├── requirements.txt
│ │ └── ... все файлы версии 0.1.2
│ ├── 0.1.3_20250122_150012/
│ └── ...
├── db/
│ └── prod_salary.db
├── prod.marker
├── desktop/
├── core/
└── version.txt
НОВАЯ ФУНКЦИЯ clean_prod_directory()

Функция очистки папки prod перед копированием новых файлов:

  • Сохраняет: .backup/, db/, prod.marker
  • Удаляет: Все остальные файлы и папки
  • Логирует: Количество удаленных и сохраненных файлов
  • Обрабатывает ошибки: Продолжает работу при ошибках удаления
Результат: Теперь перед каждым обновлением автоматически создается резервная копия текущей версии. В случае проблем с новым обновлением можно легко откатиться к предыдущей версии из папки .backup/. Это обеспечивает максимальную безопасность при обновлении production версии.

⚠️ Инструкция по использованию новой системы

Для новых проектов: Используйте first_setup.py для первоначальной настройки production окружения.

Первоначальная настройка:

  1. Запустите first_setup.bat или first_setup.py
  2. Скопируйте рабочую базу данных в prod/db/
  3. Переименуйте базу в prod_salary.db (или оставьте как salary.db - скрипт переименует автоматически)
  4. Проверьте наличие файла prod.marker в корне prod

Процесс обновления:

  1. Закройте приложение SalaryApp если оно открыто
  2. Запустите update_prod.bat или update_prod.py
  3. Следуйте инструкциям на экране
  4. Проверьте результат: Резервная копия создана в .backup/, файлы обновлены
  5. Запустите приложение из папки prod и проверьте работу

Восстановление из резервной копии:

  1. Найдите нужную версию в prod/.backup/{версия}_{дата}/
  2. Скопируйте файлы из резервной копии в корень prod
  3. Не копируйте: .backup/, db/, prod.marker (если не хотите их перезаписать)
