🚀 Скрипт деплоя scripts/deploy_to_prod.py

Зачем: ручной перенос изменений из dev-репозитория (current) в production одним запуском. Ранее деплой выполнялся скриптами в папке данных на диске D: — теперь канонический скрипт версионируется вместе с кодом в ./scripts.

Что переносим и куда

current (dev, git)
→
deploy_to_prod.py
→
production
  • Источник: ...\CODE\MyHobby\SalaryApp\current (вычисляется относительно скрипта)
  • Цель: ...\Доходы и расходы\SalaryApp (можно переопределить аргументом)
  • Реальная БД: <DATA>\SalaryApp Data\db (в проде это симлинк)

Алгоритм

  • Проверки безопасности: источник = репо (есть version.txt), цель содержит prod.marker, источник ≠ цель.
  • Бэкап прода → prod\.backup\<версия>_<дата>\.
  • Снимок секрета bot/.env перед очисткой.
  • Очистка прода (с сохранением данных — см. ниже).
  • Копирование исходников по deploy_exclude.txt.
  • version.txt: запись очищенной версии без суффикса current (например, 1.2.20).
  • Восстановление bot/.env (прод-токен не подменяется dev-токеном).
  • Проверки ключевых файлов и итог.

Гарантии безопасности

  • 🔒 БД (db → D:), prod.marker, bot/.env — не копируются и не удаляются; симлинки при очистке не трогаются.
  • 💾 При очистке сохраняются: .backup, db, prod.marker, exports, logs, nppBackup.
  • 🧪 Режим --dry-run показывает план без единого изменения.

Найдено и исправлено при проверке через dry-run

  • SECURITYПрежний скрипт мог затереть прод-токен dev-токеном — добавлены защита bot/.env и исключение *.env.
  • FIXEDКаталог .venv (10 724 файла) не был исключён — добавлен в исключения; перенос сократился до 136 файлов (чистые исходники).
  • FIXEDДобавлена защита «источник ≠ цель» (чтобы запуск из прода не очистил его сам в себя).
  • CHANGEDversion.txt в проде теперь без суффикса current; в исключения добавлен .git.

Как пользоваться

python scripts/deploy_to_prod.py --dry-run # посмотреть план, ничего не меняя python scripts/deploy_to_prod.py # реальный деплой # или двойной клик по scripts/deploy_to_prod.bat
