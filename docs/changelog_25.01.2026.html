🎨 Добавление кнопки "Удалить год" на главной вкладке

Пользовательское удобство: Теперь пользователи могут удалять все данные за выбранный год одним кликом, что значительно упрощает управление историей.

🎯 Новый интерфейс карточки года:

2024 год
Редактировать Удалить год
Общий доход: 450 000.00 руб.
Среднемесячный: 37 500.00 руб.
Месяцев с данными: 12

Новый вид карточки года с кнопками "Редактировать" и "Удалить год"

❌ ДО версии 0.2.0:
  • Только кнопка "Редактировать"
  • Невозможно удалить весь год
  • Приходилось удалять каждый месяц отдельно
  • Нет массового управления данными
  • Ограниченный функционал управления историей
✅ ПОСЛЕ версии 0.2.0:
  • Две кнопки: "Редактировать" и "Удалить год"
  • Массовое удаление всех данных за год
  • Подтверждение перед опасным действием
  • Кнопка "Удалить год" выделена красным цветом
  • Полный контроль над историей данных

📋 Процесс удаления года:

👤 Пользователь

Нажимает кнопку "Удалить год" на карточке нужного года

↓
🎨 MainView

Показывает диалог подтверждения с предупреждением

↓
🎮 NavigationController

Обрабатывает подтверждение и вызывает SalaryAPI

↓
🔌 SalaryAPI

Вызывает SalaryService и возвращает стандартизированный ответ

↓
⚙️ SalaryService

Вызывает SalaryRepository для удаления всех записей за год

↓
🗄️ База данных

Удаляет все записи за указанный год из таблицы salaries

Результат: Пользователи теперь имеют полный контроль над своими данными. Удаление всего года стало простым и безопасным процессом с подтверждением действия и немедленным обновлением интерфейса.

🔌 Расширение API и бизнес-логики

Архитектурные изменения: Добавлена полная цепочка методов от представления до базы данных с соблюдением принципов MVC и OOP.

Новые методы в SalaryService:

НОВЫЙ МЕТОД core/services/salary_service.py - delete_year()
@staticmethod def delete_year(year: int) -> bool: """Удалить все записи за указанный год""" try: # Получаем все записи за год salaries = SalaryRepository.get_by_year(year) # Удаляем каждую запись for salary in salaries: SalaryRepository.delete_by_id(salary.id) return True except Exception: return False
НОВЫЙ МЕТОД api/salary_api.py - delete_year()
@staticmethod def delete_year(year: int) -> Dict[str, Any]: """Удалить все данные за год""" try: success = SalaryService.delete_year(year) if success: return { 'success': True, 'message': f'Данные за {year} год успешно удалены', 'data': {'year': year} } else: return { 'success': False, 'error': 'Ошибка удаления', 'message': f'Не удалось удалить данные за {year} год' } except Exception as e: return { 'success': False, 'error': str(e), 'message': f'Ошибка при удалении данных за {year} год' }

Новые методы в NavigationController:

НОВЫЙ МЕТОД desktop/controllers/navigation_controller.py - delete_year()
def delete_year(self, year: int): """Удалить все данные за год""" try: # Запрашиваем подтверждение confirm = self.show_message( "Удаление года", f"Вы уверены, что хотите удалить все данные за {year} год?\nЭто действие нельзя отменить.", "question" ) if not confirm: return False # Вызываем API для удаления года response = SalaryAPI.delete_year(year) if response['success']: self.show_message("Успех", response['message'], "info") # Обновляем историю self.refresh_history() # Обновляем аналитику self.refresh_reports() return True else: self.show_message("Ошибка", response['message'], "error") return False except Exception as e: self.show_message("Ошибка", f"Не удалось удалить данные за год: {str(e)}", "error") return False
Результат: Создана полная архитектурная цепочка для обработки удаления года. Все изменения соответствуют принципам MVC и OOP, обеспечивая чистоту кода и легкость дальнейшего расширения.

🐛 Исправление дублирования сообщений в настройках

Обнаруженная проблема: При сохранении настроек сообщение об успешном сохранении появлялось два раза из-за дублирования логики в представлении и контроллере.

❌ ПРОБЛЕМА (до версии 0.2.0):

  • SettingsView._save_settings() показывал сообщение
  • NavigationController.save_settings() тоже показывал сообщение
  • Дублирование кода: Одна и та же логика в двух местах
  • Нарушение MVC: Представление выполняло функцию контроллера
  • Путаница для пользователя: Два одинаковых сообщения подряд

✅ РЕШЕНИЕ (в версии 0.2.0):

  • Убрано из SettingsView: Удален лишний вывод сообщения
  • Оставлено в контроллере: Контроллер отвечает за взаимодействие с пользователем
  • Соблюдение MVC: Четкое разделение ответственности
  • Чистый код: Устранено дублирование логики
  • Улучшенный UX: Сообщение показывается только один раз

Исправление в SettingsView:

ИСПРАВЛЕН desktop/views/settings/settings_view.py - _save_settings()
# БЫЛО (неправильно - дублирование): def _save_settings(self): """Сохранить настройки""" settings = {} for key, var in self.settings_vars.items(): settings[key] = var.get() if self.controller.save_settings(settings): messagebox.showinfo("Успех", MESSAGE_SUCCESS) # ⚠️ ЛИШНЕЕ сообщение!
# СТАЛО (правильно): def _save_settings(self): """Сохранить настройки""" settings = {} for key, var in self.settings_vars.items(): settings[key] = var.get() # Просто вызываем метод контроллера. Контроллер сам покажет сообщение. # Убрали повторный показ сообщения здесь, чтобы избежать дублирования. self.controller.save_settings(settings)
Результат: Устранено дублирование сообщений при сохранении настроек. Теперь сообщение показывается только один раз, что улучшает пользовательский опыт и соблюдает архитектурные принципы MVC.
