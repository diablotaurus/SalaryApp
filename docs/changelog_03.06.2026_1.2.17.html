🛡️ Группа П1 — Безопасность

Проблема: Файл bot/.env с токеном Telegram-бота отслеживался в git (был закоммичен). Кроме того, проверка «локального» запроса в web-слое считала запрос локальным, если адрес клиента не определён (None) — это «отказ в сторону доступа».
ДО изменений
  • Токен бота хранился в отслеживаемом файле bot/.env
  • Секрет попадал в историю репозитория
  • _is_local_request() пропускал None как локальный адрес
  • Не было шаблона переменных окружения для бота
ПОСЛЕ изменений
  • bot/.env убран из индекса и добавлен в .gitignore
  • Локальный файл сохранён — бот продолжает работать
  • Добавлен шаблон bot/.env.example без секрета
  • Проверка локального адреса больше не пропускает None

Ключевые изменения:

БЕЗОПАСНОСТЬ bot/.env (удалён из git), .gitignore, bot/.env.example (новый)

Токен убран из отслеживания, добавлено правило игнорирования и шаблон:

# .gitignore # Секреты бота bot/.env # bot/.env.example # Токен Telegram-бота от @BotFather. # Скопируйте этот файл в bot/.env и подставьте реальный токен. BOT_TOKEN=
ИСПРАВЛЕНО web/routes/salaries.py
# Было def _is_local_request() -> bool: return request.remote_addr in {"127.0.0.1", "::1", None} # Стало def _is_local_request() -> bool: return request.remote_addr in {"127.0.0.1", "::1"}
Важное действие для владельца: текущий токен бота остаётся в истории git, поэтому его необходимо отозвать в @BotFather (команда /revoke) и вписать новый токен в локальный bot/.env.
Результат: Секрет бота больше не попадает в репозиторий, добавлен безопасный шаблон конфигурации, а доступ к опасным web-операциям не предоставляется при неопределённом адресе клиента.

🎯 Группа П2 — Корректность

Проблема: Несколько латентных дефектов: потерянные декораторы @staticmethod, дублирующееся (расходящееся) описание схемы БД, неатомарное удаление года с «проглатыванием» ошибок и лишний пересчёт среднемесячного значения.

Ключевые изменения:

ИСПРАВЛЕНО core/services/salary_service.py — возвращены @staticmethod

Методы get_monthly_series_dto и get_year_with_all_months снова статические (как и весь класс), типизация уточнена на Optional[int]:

# Стало @staticmethod def get_monthly_series_dto(year: Optional[int] = None) -> Dict[str, Any]: ... @staticmethod def get_year_with_all_months(year: int) -> Dict[str, Any]: ...
DRY core/database/connection.py — удалён мёртвый create_tables()

Метод create_tables() нигде не вызывался (все точки входа инициализируют схему через apply_all_migrations()) и был вторым, расходящимся источником схемы. Удалён — единый источник схемы теперь миграции. Поправлен docstring в SalaryRepository.save(): уникальность пары (year, month) обеспечивает бизнес-логика add_salary.

НОВЫЙ МЕТОД core/repositories/salary_repository.py — delete_by_year()

Удаление года стало атомарным (один SQL-запрос вместо цикла), а сервис больше не «проглатывает» ошибки:

# Новый метод репозитория @staticmethod def delete_by_year(year: int) -> int: conn = DatabaseConnection.get_connection() cursor = conn.execute("DELETE FROM salaries WHERE year = ?", (year,)) conn.commit() return cursor.rowcount # Упрощённый сервис @staticmethod def delete_year(year: int) -> bool: SalaryRepository.delete_by_year(year) return True
ИСПРАВЛЕНО core/services/statistics_service.py — убран дублирующий расчёт

Значение avg_monthly_total вычислялось дважды (второй раз сразу перезаписывало первый). Лишнее присвоение удалено; итоговое значение по-прежнему задаёт единое бизнес-правило calculate_average_monthly_from_records. Поведение идентично.

Результат: Устранены потенциальные ошибки при вызове методов через экземпляр, исключён риск частичного удаления данных за год, ликвидировано расхождение схемы БД, а код статистики стал прозрачнее без изменения результата.

🧹 Группа П3 — DRY и чистота кода

Проблема: Дублирование логики форматирования сумм, мёртвые методы и классы, использование print() вместо логирования и избыточные аргументы в logger.exception.

Ключевые изменения:

DRY bot/main.py — единое форматирование сумм

Локальная функция _format_money удалена, бот теперь использует общий MoneyUtils.format_amount_plain (вывод идентичен):

# Было def _format_money(value: float) -> str: return f"{value:,.2f}".replace(",", " ") # Стало from core.utils.money import MoneyUtils ... MoneyUtils.format_amount_plain(value)
УДАЛЕНО core/services/salary_service.py — мёртвый format_amount()

Неиспользуемый метод SalaryService.format_amount удалён вместе с осиротевшими импортами SettingsRepository и config.

УДАЛЕНО core/models/salary.py — мёртвый класс Advance

Неиспользуемый dataclass Advance удалён.

УЛУЧШЕНО core/database/migrations.py — print → logging

Сообщения о применении миграций выводятся через logging вместо print(), для единообразия с остальным проектом.

УЛУЧШЕНО core/config/settings.py — корректное логирование исключений

Конструкции вида logger.exception("...", e) заменены на logger.exception("...") — трассировка прикладывается автоматически.

Результат: Форматирование денежных сумм сосредоточено в одном месте, удалён мёртвый код, логирование унифицировано. Код стал чище и проще в сопровождении без изменения поведения.
