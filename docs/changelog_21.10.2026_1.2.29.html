2. Telegram-бот

  • ADDED/cancel (а также «отмена» / «отменить» текстом) на любом шаге прерывает ввод без сохранения.
  • CHANGEDДата выплаты проверяется сразу на своём шаге теми же правилами, что при сохранении (SalaryAPI.validate_payment_date). При ошибке бот объясняет, что не так, и переспрашивает только дату — уже введённые суммы не теряются. «-» по-прежнему пропускает дату.
  • ADDEDЕсли выбран месяц, за который уже есть данные, бот показывает их и предупреждает: новые значения заменят прежние, пропуск даты («-») оставит сохранённую дату.
  • FIXEDСтикер, фото или голосовое на шаге ввода больше не вызывают ошибку в обработчике: бот просит ответить текстом.
  • /current показывает текущий год по МСК (раньше — по часам Windows).
  • Тесты маршрутизации идут через настоящие фильтры aiogram: проверяется, какой обработчик получит сообщение в каждом состоянии.

3. Desktop

Окна по центру главного окна

  • FIXEDВсе диалоги центрируются по главному окну приложения, а не по непосредственному родителю (новый модуль desktop/widgets/window_centering.py). Замечание пользователя: окно создания резервной копии появлялось не по центру.
  • FIXEDНа время расчёта размера окно скрыто. Раньше update_idletasks успевал показать его в позиции по умолчанию: окно мигало и могло остаться в углу.
  • ADDEDСтандартные окна Windows (сообщения, подтверждения, выбор цвета) ставятся по центру перехватчиком CBT (WH_CBT / HCBT_ACTIVATE): Tk не позволяет управлять их положением напрямую.
  • Окно ввода комментария к резервной копии переведено на общий BaseDialog. Положение всех окон проверено скриптом: отклонение от центра главного окна не больше 1 px.

Резервные копии

  • CHANGEDКолонка «Изменен» (всегда совпадала с «Создан») заменена комментарием; служебная метка auto_on_close показывается как «Автокопия при закрытии».
  • Размер — в KB/MB по величине (раньше «0.00 MB» для небольшой базы); подтверждение восстановления сообщает, что перед ним будет сделана автоматическая копия.
  • Время создания показывается в колонке «Создан (МСК)» — см. раздел 6.

4. Защита web-API

Web-сервер слушает только 127.0.0.1, и запросы с этого адреса доверялись без ключа. Этого недостаточно: браузер выполняет запросы чужих страниц тоже с локального адреса.

  • FIXEDDNS rebinding. Чужой домен можно направить на 127.0.0.1, и его страница получит доступ к API как «своя». Теперь без ключа доверяются только запросы, у которых и адрес, и заголовок Host локальные (localhost, 127.0.0.1, [::1]); остальным нужен X-API-Key, иначе 403.
  • FIXEDФормы с чужих сайтов. HTML-форма и text/plain отправляются браузером без CORS-проверки, поэтому чужая страница могла, например, создать или восстановить резервную копию. Теперь POST в /api/ принимается только с JSON (иначе 400, действие не выполняется). Собственный интерфейс и так отправляет JSON.
  • FIXEDЭкспорт. Файл экспорта читается в память, удаляется с диска и отдаётся из памяти: копии финансовых данных больше не накапливаются в exports/.
  • Проверено на production после деплоя: запрос с localhost — 200, с подменённым Host: evil.example — 403.

  • REFACTOREDУдалены неиспользуемые модули core/models/report.py и core/repositories/year_repository.py; годовые итоги статистика берёт напрямую из AnalyticsRepository.
  • REFACTOREDУдалены около 25 методов без вызовов: в SalaryService, SalaryRepository, AnalyticsRepository, FileUtils (остался только format_file_size), MoneyUtils, DateUtils, миграциях, навигации; ExportService.get_available_formats; диалоги ConfirmationDialog, InputDialog, ProgressDialog. Перед удалением каждый проверен поиском по всему проекту, включая тесты и точки входа.

6. Стандарт времени: UTC в данных, МСК на экране

Проект приведён к общему стандарту MyHobby (GLOBAL_TIME_STANDARD_RU.md): хранить и считать в UTC, показывать человеку в МСК. Все переходы между шкалами собраны в одном модуле core/utils/clock.py (zoneinfo, Europe/Moscow).

Как устроено хранение

  • Перед изменениями проверены обе базы (локальная и production, только чтение): все created_at / updated_at записывает сам SQLite (CURRENT_TIMESTAMP), а это всегда UTC без метки пояса. Поэтому данные не переписывались: при чтении такие значения получают метку UTC по документированному правилу.
  • Даты аванса и зарплаты — календарные даты, а не моменты времени, и по стандарту между поясами не конвертируются.

7. Экспорт и отчёты

  • FIXEDCSV сохраняется в UTF-8 с BOM, с разделителем «;» и запятой в суммах (два знака): двойной клик открывает его в русском Excel с нормальной кириллицей и числами, а не текстом. Правило «UTF-8 без BOM» относится к исходникам проекта, а не к пользовательским выгрузкам.
  • FIXEDГрафик «Средние значения по месяцам» использует то же правило, что KPI «Среднемесячно» (is_payment_complete): учитываются только месяцы с выплаченной зарплатой. Месяц, где пока есть только аванс, больше не занижает среднее. SQL-метод AnalyticsRepository.get_average_by_month удалён.

11. Обновление production

  1. Закрыть desktop-приложение production.
  2. Запустить деплой с перезапуском сервисов (web и бот изменились).
  3. Проверить заголовок окна desktop (1.2.29), метку «МСК» в новых строках logs/web.log и logs/bot.log.
python scripts/deploy_to_prod.py --restart-services

Совместимость: схема БД не менялась, миграций нет, сохранённые данные не переписывались. Новая зависимость tzdata уже установлена в системном Python 3.13, на котором работает production. Внешние клиенты web-API, отправлявшие POST не в JSON или обращавшиеся по нелокальному имени хоста без X-API-Key, получат 400/403. Возврат к 1.2.28 возможен обычным деплоем предыдущего кода; копии с меткой Z в имени он видит и восстанавливает как обычные.
