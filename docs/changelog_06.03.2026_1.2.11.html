ChangeLog: SalaryApp - версия v.1.2.11

Исправление расчета среднемесячного значения в карточке года и унификация бизнес-логики для desktop/web

Версия: v.1.2.11

Дата: 06 марта 2026 г.

Область изменений: core/models/year.py, core/services/statistics_service.py, tests/unit/core/services/test_statistics_service_average.py, version.txt

Причина изменений: в текущем месяце аванс мог учитываться в среднем до наступления даты зарплаты, что давало некорректное «Среднемесячное»

Статус: ✅ Выполнено и проверено тестами

SalaryApp v.1.2.11 current

Что было сделано

  • FIXEDИсправлен расчет среднемесячного значения в доменной модели года.
  • CHANGEDРасчет среднего вынесен в единый метод, чтобы исключить расхождения между desktop и web.
  • ADDEDДобавлены unit-тесты на ключевые сценарии (неполный текущий месяц и закрытый месяц).
  • SAFEОбновлена версия в version.txt согласно правилам проекта.

Детально по файлам

core/services/statistics_service.py
  • Добавлен метод calculate_average_monthly_from_records(records, now=None).
  • Введено единое бизнес-правило для среднего: учитывать только месяцы с суммой advance + salary > 0.
  • Текущий месяц исключается из среднего, если в нем еще нет зарплаты (salary <= 0).
  • Метод get_summary_statistics(...) теперь использует это единое правило для поля average_monthly.
core/models/year.py
  • Свойство YearSummary.average_monthly переведено на вызов единого метода из StatisticsService.
  • Устранено дублирование формулы и риск рассинхронизации между частями приложения.
tests/unit/core/services/test_statistics_service_average.py
  • Добавлен тест: текущий месяц с одним авансом не учитывается в среднем.
  • Добавлен тест: текущий месяц учитывается, если зарплата уже внесена.
  • Добавлен тест: get_summary_statistics(...) использует единое правило расчета.
version.txt
  • Версия обновлена с 1.2.10 current до 1.2.11 current.

Архитектурный результат (MVC, OOP, DRY, SOLID)

  • DRY: правило среднего теперь в одном месте.
  • SOLID (SRP): логика расчета сосредоточена в сервисном слое статистики.
  • MVC: View продолжает только отображать данные, расчет не перенесен в UI.
  • OOP: доменная модель YearSummary использует сервисный контракт, без дублирующей арифметики.
