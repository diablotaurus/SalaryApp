1) Новая настройка вида истории на Главной вкладке

Цель: дать пользователю переключение между текущим видом истории (6 столбцов x 2 ряда) и компактным поквартальным видом (3 столбца x 4 ряда) без изменения бизнес-логики данных.

Что добавлено

  • NEW В блок «Общие настройки» добавлены radiobutton-параметры вида истории.
  • CHANGE Введен новый ключ настройки: history_layout_mode со значениями standard / quarterly.
  • IMPROVE После сохранения настроек автоматически выполняется обновление Главной вкладки, чтобы изменения применялись сразу.

Как работает на Главной

  • standard: карточки годов по 1 в ряд, помесячная сетка 6x2.
  • quarterly: карточки годов по 2 в ряд, помесячная сетка 3x4.
  • Режим читается из БД-настроек с валидацией допустимых значений и fallback на standard.

2) Реализован авто-бэкап при закрытии приложения

Проблема: в интерфейсе существовала настройка «Автоматическое резервное копирование при закрытии», но фактический вызов создания backup в обработчике закрытия отсутствовал.

Что исправлено

  • FIX Добавлен реальный вызов авто-бэкапа в цепочку закрытия окна: App → NavigationController → MainTabController.
  • IMPROVE Учитываются настройки backup_auto и backup_days.
  • IMPROVE Срок хранения для очистки старых backup применяется из пользовательской настройки на момент создания копии.
  • IMPROVE Добавлена безопасная обработка ошибок с логированием, без падения приложения при закрытии.

3) Дефект переключения 3x4 → 6x2 без перезапуска

Симптом: при возврате из режима 3x4 в 6x2 карточки оставались полуширины до перезапуска приложения.

Причина

  • После режима с двумя колонками сохранялась конфигурация второй колонки контейнера карточек.

Решение

  • FIX Перед применением нового режима добавлен сброс column-конфигурации контейнера карточек.
  • После сброса повторно настраивается нужное количество колонок для текущего режима (1 или 2).

Измененный файл

desktop/views/main/main_view.py
Результат: теперь переключение в обе стороны (6x2 ↔ 3x4) применяется сразу, без перезапуска.
