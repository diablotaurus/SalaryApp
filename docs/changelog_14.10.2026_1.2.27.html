2. Telegram-бот: несколько прокси без отката на прямое подключение

Причина падений

На этом ПК Telegram доступен только через локальный SOCKS5-прокси. Если прокси в момент запуска не отвечал, bot/main.py переходил на прямое подключение. Оно не устанавливалось (около 21 с ожидания соединения в Windows), polling останавливался, процесс завершался с кодом 1, и задача Планировщика SalaryAppBot с перезапуском при сбое запускала бота снова. Получался бесконечный цикл падений.

Что изменено

  • FIXEDОткат на прямое подключение при заданном прокси удалён. Если сейчас не отвечает ни один прокси, бот использует предпочтительный и ждёт его восстановления: aiogram сам повторяет попытки, процесс не завершается.
  • ADDEDTELEGRAM_PROXY принимает несколько адресов через запятую или точку с запятой в порядке приоритета. Пустые значения и повторы отбрасываются (load_proxies() в bot/config.py).
  • При запуске прокси проверяются по очереди запросом get_me с таймаутом 8 с; используется первый ответивший. В лог пишется, через какой прокси установлено подключение, и какие прокси недоступны.
  • Прямое подключение по-прежнему используется, если прокси не задан вовсе.
  • load_proxy() сохранён для обратной совместимости и возвращает первый прокси из списка.
  • bot/.env.example описывает формат с несколькими прокси.
  • TESTДобавлены тесты на старый ключ ALLOWED_USER_IDS и приоритет канонического BOT_ALLOWED_IDS.
# bot/.env: предпочтительный (более стабильный) прокси первым
TELEGRAM_PROXY=socks5://192.168.0.8:10820,socks5://192.168.0.8:10808

Проверка в production: исправление развёрнуто 14.10.2026 до оформления релиза, в production-файле bot/.env задан список из двух прокси. После перезапуска лог показал подключение через 10820 и начало polling. Позднее была кратковременная потеря связи с Telegram: бот восстановил соединение сам примерно через 11 с, без завершения процесса.

3. Подсказки на графике «Помесячные данные»

  • ADDEDПри наведении курсора на столбец показывается подсказка: месяц, год и сумма с подписью ряда («Аванс», «Зарплата» или «Итого»).
  • Работает в обоих режимах графика: за один год (три ряда) и за все годы (итог по месяцам).
  • Текст подсказок готовит ChartPresenter; привязку к столбцам и показ выполняет новый класс BarChartTooltip через события matplotlib. Подсказка не выходит за край графика и скрывается при уходе курсора.
  • Оформление вынесено в константы chart_constants.py.

4. Ускорение desktop-интерфейса

Замеры выполнены на копии production-БД (4 года данных) на рабочем ПК. Копия создавалась через SQLite Backup API в режиме только чтения и удалялась после замеров; рабочая БД не изменялась.

Действие1.2.261.2.27
Переключение на «Главную»2.4–3.0 с, с миганием~0.2 с
Переключение на «Аналитику»0.4–0.6 с~0.1 с
Запуск до готового окна~4.6 с~2.0–2.4 с
Первое открытие «Аналитики» за сеанс~0.5 с~1.3 с (один раз за сеанс)

Чтение данных из БД для вкладок занимает около 1 мс; основное время уходило на интерфейс. Изменения выполнены тремя согласованными шагами.

П1. Перерисовка только при изменении данных

  • ADDEDRenderCache (desktop/controllers/render_cache.py) запоминает данные последней отрисовки.
  • MainTabController.refresh_history читает данные и настройки при каждом переключении и перестраивает карточки только при их изменении.
  • ReportTabController.load_chart_data сначала собирает данные четырёх графиков и KPI, затем перерисовывает только при их изменении или смене года.
  • Записи, добавленные через бота или Web, по-прежнему появляются: данные читаются при каждом переключении. После ввода, удаления, восстановления из бэкапа и сохранения настроек вкладки перерисовываются как раньше.
  • MainView.display_years больше не сортирует переданный список на месте.

П3. Ячейка месяца на одном Canvas

  • REFACTOREDНовый класс MonthCell (desktop/views/main/month_cell.py) рисует название месяца, строки «Аванс»/«Зарплата» с датой и суммой, «Итого» и «Нет данных» на одном Canvas вместо ~11 виджетов.
  • Раскладка повторяет прежнюю: поля tk.Label, отступы pack/grid и деление свободной ширины между колонками даты и суммы. Шрифты и цвета из настроек создаются один раз на отрисовку (MonthCellStyle).
  • Три прежних метода сборки ячейки в MainView удалены.
  • FIXEDВысота зоны выплат считается по реальной высоте двух строк. Прежняя формула от размера шрифта в пунктах занижала её, и на крупных шрифтах (от 12 pt) строка «Зарплата» обрезалась снизу.

Проверка внешнего вида: скриншоты главной вкладки до и после изменения сравнивались попиксельно на копии production-БД в стандартном режиме и режиме «по кварталам». На текущих размерах шрифтов (9/10/10 pt) отличий нет. На крупных шрифтах единственное отличие: строка «Зарплата» видна целиком.

Ограничение: при максимальном размере шрифтов (18 pt) в стандартном режиме шесть ячеек в ряд не помещаются в ширину окна ни в старой, ни в новой версии. В новой версии сумма обрезается правым краем ячейки. При крупных шрифтах рекомендуется режим «по кварталам».

П4. Вкладка «Аналитика» строится при первом открытии

  • CHANGEDПри создании ReportView показывает только надпись «Загрузка графиков…». matplotlib импортируется, а панели и графики строятся в ensure_built() при первом обращении к вкладке.
  • ReportTabController.refresh_reports достраивает вкладку перед обновлением данных.
  • Если «Аналитику» в текущем сеансе ещё не открывали, удаление года или восстановление из бэкапа один раз займёт примерно на 1 с дольше: после этих операций аналитика обновляется сразу.
  • TESTТест проверяет, что импорт desktop.app не загружает matplotlib. Это защищает скорость запуска от случайных будущих правок.

8. Обновление production

  1. Закрыть desktop-приложение production.
  2. Запустить согласованный скрипт deploy из dev-каталога. Маркер production и защищаемый bot/.env сохраняются.
  3. Для бота: в production-файле bot/.env должен быть задан TELEGRAM_PROXY со списком прокси (уже сделано 14.10.2026). Код бота в этом релизе тот же, что уже работает в production, поэтому перезапуск бота не обязателен.
  4. Web не менялся, перезапуск SalaryAppWeb не нужен.

Совместимость: схема БД и зависимости не менялись, миграций нет. Возврат к 1.2.26 возможен обычным деплоем предыдущего кода; нужно только учесть, что старый бот снова будет переходить на прямое подключение при недоступном прокси.
