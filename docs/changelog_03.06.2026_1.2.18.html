📝 Группа Б2.1–Б2.2 — Логирование и гигиена исключений

Проблема: Сервис резервного копирования выводил сообщения и ошибки через print() — в desktop-режиме (.pyw) консоли нет, поэтому сообщения терялись. Дополнительно встречались «голые» except:, перехватывающие в том числе прерывание пользователем.
ДО изменений
  • 6× print() в backup_service.py
  • Ошибки не попадали в лог-файлы
  • Голые except: в backup/export сервисах
ПОСЛЕ изменений
  • logger.info / logger.exception с трассировкой
  • Сообщения попадают в общий лог приложения
  • except Exception: вместо голого except
УЛУЧШЕНО core/services/backup_service.py
# было except Exception as e: print(f"Error restoring backup: {e}") # стало except Exception: logger.exception("Error restoring backup")
ИСПРАВЛЕНО core/services/export_service.py, core/services/backup_service.py

Голые except: заменены на except Exception:.

♻️ Группа Б2.3–Б2.4 — DRY и удаление мусора

DRY core/services/export_service.py

Список названий месяцев больше не дублируется — используется единый источник DateUtils.get_month_name:

# было month_names = ['Январь', ..., 'Декабрь'] month_name = month_names[row['month'] - 1] # стало month_name = DateUtils.get_month_name(row['month'])
УДАЛЕНО core/services/backup_service.py, core/services/export_service.py

Удалён неиспользуемый import sqlite3 в обоих сервисах.

🧹 Группа Б3 — Удаление мёртвого и недостижимого кода

Проблема: В проекте оставались артефакты прошлых итераций: неиспользуемый виджет таблицы и устаревшие методы презентера графиков, недостижимые при текущем потоке данных.
УДАЛЕНО desktop/widgets/tables.py (класс EditableTable)

Класс EditableTable нигде не инстанцировался (только реэкспорт). Файл удалён, импорт из desktop/widgets/__init__.py убран.

УДАЛЕНО desktop/presenters/chart_presenter.py (4 legacy-метода)

Удалены устаревшие prepare_monthly / prepare_yearly / prepare_growth / prepare_average (для старого формата {labels, datasets}). Контроллер аналитики всегда передаёт DTO с ключом items, поэтому эти методы были недостижимы.

УПРОЩЕНО desktop/views/report/report_view.py

4 ветки построения графиков упрощены — недостижимый fallback на legacy-методы убран:

# было else: model = self.presenter.prepare_monthly(data) if data else {"has_data": False} # стало else: model = {"has_data": False}
Результат: Кодовая база стала меньше и понятнее, исчезли «мёртвые» ветки, которые усложняли чтение и сопровождение модуля аналитики.

🏛️ Группа Б2.5 + развязка — Архитектура API

Цель: Привести SettingsAPI к единому стилю ответов остального API и устранить нездоровую связанность между пакетами.
РЕФАКТОРИНГ api/settings_api.py

Методы переписаны на общие хелперы (success / failure / execute_with_default_error), убраны вводящие в заблуждение docstring про несуществующее «кэширование». Форма ответа сохранена.

ПЕРЕМЕЩЕНО api/salary_api_modules/common.py → api/common.py

Общие хелперы ответов вынесены на уровень пакета api, чтобы settings_api не зависел от внутреннего пакета salary_api_modules. Обновлены 5 импортов (queries, commands, maintenance, analytics, settings_api).

settings_api
→
api/common
←
salary_api_modules/*
Нюанс поведения: в рамках унификации SettingsAPI теперь перехватывает RECOVERABLE_EXCEPTIONS (как и весь API), а не «любой Exception». Это консистентно с SalaryAPI; web-роуты перехватывают остаток на своей границе.
Результат: Единый стиль ответов во всём API, отсутствие межпакетной связанности, корректная документация.
