1. Обнаруженная проблема

После публикации коммита 96231a9 локальная проверка и GitHub Actions дали разные результаты. В рабочем каталоге прошли 110 тестов, а на чистых Windows runner с Python 3.11, 3.12 и 3.13 прошли 109 тестов и завершился ошибкой один и тот же сценарий:

test_main_tab_controller_refresh_history
sqlite3.OperationalError: no such table: settings

Результат исходного запуска сохранён в GitHub Actions для версии 1.2.25. Проверки критических правил Ruff и runtime-зависимостей в этом запуске прошли; отдельная проверка кодировок тоже была успешной.

  1. Контроллер истории получает данные зарплаты через SalaryAPI, затем настройки через SettingsAPI.get_settings().
  2. В unit-тесте был подменён только запрос зарплаты. Запрос настроек проходил через сервис и репозиторий в настоящую SQLite-БД.
  3. Существующая локальная таблица settings скрывала зависимость теста от окружения. Чистая копия репозитория не содержит пользовательскую БД.
  4. При повторении проверки с пустой SQLite-БД в памяти ошибка воспроизвелась. Временная подмена API настроек устранила сбой без изменения приложения.

Вывод: это дефект изоляции unit-теста. Для его исправления не нужно включать рабочую БД в Git, создавать production-данные в CI или отключать проверку.

2. Выполненное исправление

FIXEDВ существующий тест добавлена подмена API настроек через уже используемый monkeypatch:

monkeypatch.setattr(
    "api.settings_api.SettingsAPI.get_settings",
    lambda: {"success": True, "data": {}},
)
  • Ответ сохраняет реальный контракт API: признак успеха и словарь настроек. Пустой словарь достаточен для существующего сценария проверки отображения истории.
  • Существующая проверка результата display_years сохранена. Тест не удалён, не пропущен и не помечен ожидаемо падающим.
  • Подмена ограничена временем выполнения теста и автоматически отменяется pytest.
  • Использован тот же подход, что в соседнем тесте аналитики. Новые функции, методы и классы в проект не добавлены.

Разделение ответственности: unit-тест контроллера изолирован на границе API. Проверки реальных настроек, репозиториев и миграций остаются в своих тестах с временными БД. Рабочая логика MVC и публичные контракты не изменены.
